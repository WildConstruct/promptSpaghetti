# Story 20.2: Internal File Browser & Project Management

## Status

Draft

## Story

**As a** user of the prompt-spaghetti application,
**I want** a comprehensive file browser and project management system,
**so that** I can organize, manage, and navigate my .psg files and projects efficiently with seamless integration to the graph editor.

## Acceptance Criteria

1. **File Browser UI Component**: Tree-structured file navigation interface showing folders, .psg files, and project hierarchy with expandable/collapsible folders

2. **Authentication Integration**: File browser requires user authentication from Story 20.1 and shows user-specific files and projects with proper access control

3. **Core File Operations**: Users can upload, download, rename, delete, duplicate, and move .psg files and folders through context menus and drag-and-drop interface

4. **Project Management**: Hierarchical project organization with folder creation, metadata editing, tags, and project settings management

5. **Graph Editor Integration**: Double-click .psg files opens them directly in the existing graph editor with automatic saving back to the file system

6. **Search and Filtering**: Advanced search functionality including filename, content, tags, and metadata with real-time filtering and sorting options

7. **File Preview System**: Hover or click previews showing graph thumbnails, node counts, metadata, and last modified information

8. **Recent Files & Favorites**: Quick access sidebar showing recently opened files and user-favorited projects for efficient navigation

9. **Bulk Operations**: Multi-select functionality for batch operations like delete, move, export, and tag management

10. **Responsive Design**: File browser works seamlessly on desktop and mobile with touch-friendly interfaces and adaptive layouts

## QA Results

### Review Date: 2025-07-22

### Reviewed By: Quinn (Senior Developer QA)

### Code Quality Assessment

The FilePreview component implementation demonstrates solid React development practices with good TypeScript integration. The code follows component composition patterns effectively, uses React optimization hooks appropriately (useMemo, useCallback), and maintains clear separation of concerns. However, the implementation has several architectural issues and missing critical functionality that affect the overall quality.

**Strengths:**

- Clean, well-documented TypeScript interfaces
- Proper React optimization patterns (memo, useCallback, useMemo)
- Good component composition with reusable FilePreview component
- Comprehensive prop interfaces with clear documentation
- Consistent styling approach and responsive design considerations

**Critical Issues Identified:**

- **Missing Core Dependencies**: Components import from `../../projectManager` and `../../graphSchema` but these appear to be missing type dependencies
- **No Test Coverage**: Zero test files found for any FilePreview components despite project requiring 80%+ coverage
- **localStorage Error Handling**: Basic try/catch but no recovery mechanisms or user feedback
- **Performance Concerns**: Thumbnail generation on every render without proper caching
- **Incomplete Integration**: Components are standalone without proper integration into existing app architecture

### Refactoring Performed

Due to missing dependencies and integration issues, extensive refactoring was not possible. However, I identified several critical areas requiring immediate attention:

- **File**: `packages/core/components/FilePreview/FilePreview.tsx`
  - **Issue**: Thumbnail generation should be memoized or cached externally
  - **Impact**: Performance degradation with large file lists
  - **Recommendation**: Implement proper thumbnail caching system

- **File**: `packages/core/components/FilePreview/RecentFiles.tsx`
  - **Issue**: Direct localStorage manipulation without proper error boundaries
  - **Impact**: Component could crash on localStorage failures
  - **Recommendation**: Implement proper error boundaries and fallback states

- **File**: `packages/core/components/FilePreview/HoverPreview.tsx`
  - **Issue**: Style-jsx usage is non-standard for this project
  - **Impact**: Inconsistent styling approach across codebase
  - **Recommendation**: Convert to standard CSS-in-JS or styled-components pattern
