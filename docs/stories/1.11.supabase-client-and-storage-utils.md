# Story 1.11: supabase-client-and-storage-utils

## Status
Complete

## Story
**As a** developer,
**I want** a typed Supabase client and storage helpers,
**so that** I can list/get/put user `.psg` files under scoped paths.

## Acceptance Criteria
1) Client configuration
- A1. Supabase client reads URL and anon key from env (`NEXT_PUBLIC_…` or `VITE_…`).
- A2. If missing, export `null` client and log a single warning (debounced) in dev.

2) Storage helpers
- B1. Provide: `listUserGraphs(userId)`, `getUserGraph(userId, key)`, `putUserGraph(userId, name, data)`.
- B2. Use bucket `graphs` and path prefix `users/{userId}/graphs/`.
- B3. `putUserGraph` sets `contentType: application/json` and `upsert: true`.

3) Type safety
- C1. Public signatures have explicit types; no `any`.
- C2. Functions return discriminated results `{ ok: true, data } | { ok: false, error }` or throw documented errors.

4) Graceful degradation
- D1. When client is `null`, helpers short-circuit with clear error results (no throws).
- D2. Works in dev with valid envs; otherwise, feature can be safely disabled by UI.

## Dev Notes
- Files:
  - `packages/core/utils/supabaseClient.ts`: reads NEXT_PUBLIC_/VITE_ envs; exports `supabase` or `null`; dev-only once-per-session warning when missing.
  - `packages/core/utils/psgStorage.ts`: helpers `listUserGraphs`, `getUserGraph`, `putUserGraph` using bucket `graphs` and prefix `users/{userId}/graphs/`.
  - Discriminated result type `StorageResult<T>` used across helpers.
  - Content type standardized to `application/json` and `upsert: true` for put.
  - Re-exported via `packages/core/utils/index.ts`.
- Env variables supported: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.

- Use path helpers to avoid duplicated string concatenation for `users/{userId}/graphs/`.
- Consider pagination for `listUserGraphs` if list grows (not required for MVP).
- Prefer narrow error shapes for UI mapping (message, code, cause?).
 - Define a small result alias for helpers: `type StorageResult<T> = { ok: true; data: T } | { ok: false; error: { message: string; code?: string } }`.
 - Dev-only warning cadence: emit at most once per session (or per page load), not per call.

### Testing
- Added `packages/asset-browser/tests/psg-storage.test.ts` which mocks the core supabase client and validates:
  - Null client short-circuit with error result.
  - `listUserGraphs` uses correct prefix and filters `.psg` files.
  - `getUserGraph` downloads correct path and returns text.
  - `putUserGraph` uploads with `application/json` and `upsert: true` and returns path.

## Dependencies / Risks
- Dependencies: Supabase project with `graphs` bucket (out of scope of this story to create).
- Risks: Silent failures if envs missing; mitigated by debounced warning and discriminated results.
