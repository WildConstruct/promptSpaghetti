# Story 1.4: Restore Inline Segmentation Editor on Launch Screen (Brownfield Addition)
 > DEPRECATED: Use canonical file `docs/stories/1.4.inline-seg-editor-restoration.md`.

Status: Ready

## Story
As a prompt author,
I want the pasted prompt to be auto-parsed into colored, editable segments with inline controls (split, type switch, delete) in a single primary view,
so that I can quickly correct parsing errors, adjust segment boundaries, and keep the node graph in sync without switching modes.

## Story Context (Existing System Integration)
- Integrates with: `client/src/components/LaunchScreen/PromptDissector.tsx`, `client/src/components/LaunchScreen/SegmentMarker.tsx`, `client/src/lib/simplePromptParser.ts`
- Technology: React + TypeScript + CSS modules
- Follows pattern: Debounced parse -> overlay highlights -> `onAnalysisComplete` -> node graph sync
- Touch points: Inline toolbar, inline segment menu, split handlers, node type updates, delete mapping, Edit Mode toggle, reconciliation on OK

## Acceptance Criteria
1) Auto-Parse to Color Blocks
- Paste or edit text in the wizard textarea causes a debounced parse (~300ms) and renders colored highlight segments overlaying the text.
- Segments and color blocks are derived from `simplePromptParser.parse()` mappings; un-mapped text remains unhighlighted.
- Colors remain stable for existing nodeIds where possible across re-parses.

2) Text Still Editable
- The underlying `textarea` remains focusable and editable at all times in “editor with highlights” mode.
- Cursoring, selecting, and typing in the `textarea` updates the parsed overlay on debounce without UI glitching.

3) Inline Toolbar Above Text
- An inline toolbar (positioned above the text area) provides at least: Undo, Redo, Split at Cursor (operates within the segment intersected by the cursor), Split Selection (creates a new mapping for the selection via a modal and tri-splits if selection is inside an existing mapping).
- Buttons are disabled/enabled appropriately based on available actions.
- Toolbar remains visible and clickable, with appropriate z-index, in all states.

4) Consolidation of Chiclet/Segment Editor Functionality Into One Primary View
- Clicking a highlighted segment shows an inline menu over the text, containing: Delete segment mapping (see AC-5), Node type switcher (Text, Choice, Variable).
- The inline menu appears only for the active/selected segment; it is rendered opaque over text with pointer events enabled and does not allow the underlying text to intercept clicks.
- The node type switch updates the analysis nodes in-place and the overlay immediately reflects the new type.

5) Delete Mapping Behavior
- Clicking “Delete” on a segment removes the node mapping and node; the underlying text remains intact as plain, unhighlighted text.
- Deleting in the middle of the text recomputes neighboring plain segments as needed without breaking index consistency; triggers a light re-parse to merge adjacent plain text.

6) Edit Mode Toggle (Full Text Edit)
- An “Edit” button (bottom-right of the prompt panel) switches to a “standard text editing mode” that hides the highlight overlay and inline controls.
- In Edit Mode, the user can freely change the entire prompt; show OK ("Apply Changes") and Cancel ("Discard") buttons in a bottom bar.
- On Cancel (or Escape key), return to previous analysis without reconciliation, preserving scroll/focus. On OK (or Enter), reconcile the edited text (see AC-7) and update nodes, mappings, and colors.

7) Reconciliation on OK (Diff + Best-Match Remap)
- On OK from Edit Mode, the app attempts to match existing nodes to the new text using a best-effort heuristic (e.g., longest common substring >70% similarity + relative ordering).
- Preserves nodeIds for matched segments and retains their node types and colors where feasible (target ~80% retention on minor edits).
- Generates new nodeIds for unmatched segments; removes nodes that can't be matched.
- Produces an updated `PromptAnalysis` with nodes and mappings ordered by position, keeping Output node last.
- Result is emitted via `onAnalysisComplete(updated)` and immediately reflected in the overlay view.

8) Overlay Interaction and Accessibility
- Overlay highlight spans and inline menus have appropriate z-index and pointer-events (none for plain highlights, auto for menus) so menus are fully clickable.
- Inline menu buttons have accessible labels/titles (e.g., aria-label="Delete segment") and are keyboard-focusable.
- Text color, contrast, and selection remain legible with highlights active (aim for WCAG 2.1 AA).

9) Performance and Stability
- Debounced parsing and rendering complete within 300ms for prompts up to 2–3k characters on standard dev machines (aim <500ms on mobile/low-spec).
- Undo/Redo works across split, mapping, and type changes.
- No console errors; debug logs remain where useful but are not excessively noisy.

10) Visual Consistency
- Colored highlights use the existing palette from `PromptDissector` and `SegmentMarker`.
- Inline menus are visually opaque over text and do not flicker during scrolling or editing.

11) Removal of Separate Chiclet Mode
- Prior “chiclet/pill” segmented view is functionally replaced by the consolidated primary view. All previously useful chiclet actions (delete, type switch) are available inline on the selected segment in the main editor.

12) QA Validation
- Manual test: Paste the octopus sample prompt; verify segment colors, split operations, type changes, delete behavior, Edit Mode flow, and reconciliation results (target ~80% match on minor edits).
- Node counts and mapping counts reflect the visible overlay state; changes propagate to the node graph via `onAnalysisComplete`.
- Edge cases: Multi-segment splits, parse failures (show toast), long prompts (no lag).

## Tasks / Subtasks

### Implementation
- UI Layer
  - Update `client/src/components/LaunchScreen/PromptDissector.tsx`:
    - Ensure inline toolbar (Undo/Redo/Split at Cursor/Split Selection) with stable z-index and pointer events.
    - Add "Edit" button (bottom-right) to toggle Edit Mode and hide overlay/inline controls.
    - Ensure overlay spans do not block typing; plain highlights use `pointer-events: none`, inline menu uses `pointer-events: auto`.
  - Extend `client/src/components/LaunchScreen/SegmentMarker.tsx`:
    - Add Delete action to inline menu next to T/C/V.
    - Confirm `onChangeNodeType` updates analysis; add `onDelete` to remove mapping/node.
    - Ensure inline menu is opaque, with proper z-index, keyboard focus, and titles/aria-labels.
- Logic Layer
  - Create `client/src/lib/analysisReconciler.ts`:
    - Implement best-effort matching (LCS + relative order/proximity; similarity threshold ~0.7).
    - Preserve IDs/types/colors for matched segments; generate new IDs for unmatched.
    - Return updated `{nodes, mappings}` and keep Output node last.
  - Update `client/src/lib/simplePromptParser.ts`:
    - Support light re-parse path after delete to merge adjacent plain ranges without index drift.
- Styles
  - Update `client/src/components/LaunchScreen/PromptDissector.css` and `client/src/components/LaunchScreen/SegmentMarker.css` for opacity/z-index, contrast, menu hit areas, and focus rings.
- State/Events
  - Ensure `onAnalysisComplete` fires after split/delete/type changes and after Edit Mode OK.
  - Maintain undo/redo stacks consistently for mapping changes inside `PromptDissector`.

### Testing
- Unit tests for `analysisReconciler.ts` covering: no-op edit; small insertion; deletion; splitting a segment; merging two segments; large rewrite.
- Component tests for: Split at Cursor; Split Selection; Delete; Type switching; Edit Mode OK/Cancel.
- Accessibility checks for inline menu focusability and labels.

### QA Scenarios
- Octopus prompt: run through all controls and verify node/mapping counts and visual alignment.
- Stress test: ~2–3k chars to confirm performance and stability.

  - `client/src/lib/analysisReconciler.ts` – best-effort matching to preserve nodeIds and update `{nodes, mappings}`; keep Output last.
- Behavior specifics:
  - Delete removes mapping/node and leaves underlying text unchanged.
  - Type switching updates the `nodeType` in analysis immediately.
  - Overlay spans default to `pointer-events: none`; inline menus use `pointer-events: auto` and a higher `z-index`.
- Performance: keep parse debounce around 300ms; minimize overlay DOM churn.
- Edge cases: Multi-boundary splits; error toasts for failures.
