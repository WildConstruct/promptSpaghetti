# Story 1.6: Asset Browser – Side-car `.psglib` Ingestion & Manifest Scan (P2)

## Status
Ready for Dev

## Story
**As a** graph editor user,
**I want** the Asset Browser to discover and index presets from `.psglib` side-cars via a library manifest scan,
**so that** I can browse and insert available presets without manual import steps.

## Acceptance Criteria
1. Library scan loads presets from one or more root locations, supporting both minimal and npm-style manifest formats.
2. `.psgmanifest` is parsed; each preset entry resolves to a `.psglib` file and is validated against schema v1.0 (name, tags, nodeTypes, engineVersion, thumbnail, lastModified, author, outputType).
3. The browser state contains a normalized preset index (id, name, tags, path, content-hash thumbnail key, nodeTypes) exposed via `usePresetLibrary`.
4. Tag filtering in Sidebar operates on the loaded index; empty state and error state are handled.
5. CLI parity: design accounts for `rebuild-manifest` conversion between minimal and npm-style formats (runtime supports reading both; conversion is not implemented in UI).
6. Performance: initial scan of a library with 50+ presets completes within acceptable time and does not block UI (async with progress indicator).
7. Unit tests cover manifest parsing (both formats), schema validation, index building, and tag filtering behavior.

### Manifest Examples (for dev reference)
- Minimal `.psgmanifest` example:
```json
{
  "presets": [
    { "id": "wc-basic", "path": "./wc-basic.psglib", "tags": ["writing"], "nodeTypes": ["LLM"], "thumbnail": "thumbs/wc-basic.png" }
  ]
}
```
- npm-style manifest excerpt:
```json
{
  "name": "@org/preset-library",
  "version": "0.1.0",
  "presetLibrary": {
    "presets": [
      { "id": "wc-basic", "path": "dist/wc-basic.psglib", "tags": ["writing"], "nodeTypes": ["LLM"], "thumbnail": "dist/thumbs/wc-basic.png" }
    ]
  }
}
```

### Error Reporting Format
- Collect parse/validation errors and group by file. Example structure:
```ts
type ScanError = { file: string; issues: Array<{ path: string; message: string }> };
```
- Display a concise summary in UI (e.g., “3 errors across 2 files”), with optional details expandable in dev builds.
