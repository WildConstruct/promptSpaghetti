# Story 1.29: PSGLib File Format Implementation

## Status
Done

## Story
**As a** content creator,
**I want** to save and load reusable graph components as .psglib preset files,
**so that** I can build a library of shareable building blocks for prompt generation.

## Acceptance Criteria
1) File Format Implementation
- A1. Implement .psglib file parser that reads the v1.0 schema format
- A2. Implement .psglib file writer that exports valid preset files
- A3. Support both single-node and multi-node preset exports

2) Export Functionality
- B1. "Save as Preset" option in context menu for selected nodes
- B2. Export dialog captures preset metadata (name, tags, description, author)
- B3. Validates and saves as .psglib file to chosen location
- B4. Optionally saves to preset library directory for immediate availability

3) Import Functionality
- C1. "Insert Preset" loads .psglib file and adds nodes to current graph
- C2. Handles node ID regeneration to avoid conflicts
- C3. Positions imported nodes at cursor/drop location
- C4. Maintains all node connections within the preset

4) Integration
- D1. Exported .psglib files are discovered by existing manifest scanner (Story 1.6)
- D2. Asset Browser displays available presets from .psglib files
- D3. Drag-and-drop from Asset Browser inserts preset into graph

5) Sample Library
- E1. Create 10-15 sample .psglib files covering common patterns
- E2. Include character generators, story elements, world-building blocks
- E3. Document preset creation best practices

6) Error Handling
- F1. Gracefully handle corrupted/invalid .psglib files with user-friendly error messages
- F2. Display clear error when version mismatch detected (offer migration if possible)
- F3. Prevent duplicate preset IDs with conflict resolution dialog
- F4. Show progress indicator for large preset imports (>10 nodes)
- F5. Validate circular dependency prevention before import completion

7) Analytics Integration (PM Requirement)
- G1. Track preset usage events (preset_id, timestamp, user_action)
- G2. Track preset creation patterns (nodes_included, tags_used, complexity)
- G3. Send analytics data to tracking service (if enabled)
- G4. Include usage_count in preset metadata for popularity tracking

8) Future-Proofing (PM Requirement)
- H1. Add "license" field to metadata (MIT, CC-BY, proprietary, etc.)
- H2. Add "usageStats" object for tracking times_used, last_used
- H3. Ensure "formatVersion" supports semantic versioning for compatibility
- H4. Reserve metadata fields for marketplace integration (price, ratings)

## Dev Notes
### PSGLib Schema v1.0 (Updated with PM Requirements)
```json
{
  "fileType": "psglib",
  "formatVersion": "1.0.0",
  "metadata": {
    "id": "unique-preset-id",
    "name": "Preset Name",
    "description": "What this preset does",
    "author": "Author Name",
    "version": "1.0.0",
    "tags": ["character", "fantasy"],
    "nodeTypes": ["WeightedChoice", "Concat"],
    "thumbnail": "content-hash-key",
    "lastModified": "2025-08-08T10:00:00.000Z",
    "license": "MIT",  // NEW: For future marketplace
    "usageStats": {    // NEW: Analytics tracking
      "timesUsed": 0,
      "lastUsed": null,
      "popularity": 0
    },
    "marketplace": {   // NEW: Reserved for future
      "price": null,
      "rating": null,
      "downloads": 0
    }
  },
  "graph": {
    "nodes": [...],
    "edges": [...],
    "settings": {...}
  }
}
```
