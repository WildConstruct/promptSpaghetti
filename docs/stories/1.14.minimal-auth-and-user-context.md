# Story 1.14: minimal-auth-and-user-context

## Status
Implemented

## Story
**As a** user,
**I want** the app to know my userId when storage is enabled,
**so that** cloud save/open works under my own scoped folder.

## Acceptance Criteria
1) Provider contract
- A1. A `useUserId()` (or equivalent) hook returns `{ userId: string | null }` and is accessible in dialogs.
- A2. The provider updates reactively when sign-in state changes (if applicable).

2) Gating
- B1. If not authenticated or userId missing, Supabase features are hidden/disabled gracefully.
- B2. When hidden, no Supabase calls are made.

3) Dev/demo stub
- C1. A deterministic dev userId is available (e.g., stored in localStorage) behind a dev flag.
- C2. Alternatively, Supabase anon session can provide a stable user id.

4) Security
- D1. No secrets are committed; env-driven configuration only. Document expected envs.

## Usage

Wrap your app (or the portion that uses the dialogs) with `UserProvider`. Pass a Supabase client if available; otherwise enable a deterministic dev user via an env flag.

```tsx
import React from 'react';
import { UserProvider, OpenGraphDialog, SaveGraphDialog } from '@prompt/asset-browser';
import { listUserGraphs, getUserGraph, putUserGraph } from '@prompt/core/utils';

const enableSupabase = Boolean(
  process.env.NEXT_PUBLIC_SUPABASE_URL || process.env.VITE_SUPABASE_URL
) && Boolean(
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY || process.env.VITE_SUPABASE_ANON_KEY
);

export function AppShell({ supabase }: { supabase?: any }) {
  return (
    <UserProvider supabase={supabase}>
      {/* userId is picked up from context by both dialogs */}
      <OpenGraphDialog
        isOpen
        onClose={() => {}}
        onOpenGraph={(g) => {/* ... */}}
        enableSupabase={enableSupabase}
        supabaseList={listUserGraphs}
        supabaseGet={getUserGraph}
      />
      <SaveGraphDialog
        isOpen
        onClose={() => {}}
        graph={{}}
        enableSupabase={enableSupabase}
        supabasePut={putUserGraph}
      />
    </UserProvider>
  );
}
```

Notes:
- Both dialogs accept an explicit `userId` prop, but it is optional when wrapped with `UserProvider`.
- The provider exposes `useUserId()` returning `{ userId: string | null }` for other components.

### Environment Variables
- Dev user flag: set `NEXT_PUBLIC_FEATURE_DEV_USER=1` (Next.js) or `VITE_FEATURE_DEV_USER=1` (Vite) to enable a deterministic dev user.
- Dev user storage key: `psg.devUserId` in `localStorage`.
- Supabase: `NEXT_PUBLIC_SUPABASE_URL`/`ANON_KEY` or `VITE_SUPABASE_URL`/`ANON_KEY`.

Implementation detail: the dev flag is evaluated at runtime to support tests and dynamic environments, and Supabase `onAuthStateChange` is safely unsubscribed when available.
