# Story 1.4: Restore Inline Segmentation Editor on Launch Screen (Brownfield Addition)

## Status
Ready

## Story
**As a** prompt author,
**I want** the pasted prompt to be auto-parsed into colored, editable segments with inline controls (split, type switch, delete) in a single primary view,
**so that** I can quickly correct parsing errors, adjust segment boundaries, and keep the node graph in sync without switching modes.

## Acceptance Criteria
1. **Auto-Parse to Color Blocks**
   - Paste or edit text in the wizard textarea causes a debounced parse (~300ms) and renders colored highlight segments overlaying the text.
   - Segments and color blocks are derived from `client/src/lib/simplePromptParser.ts` mappings; un-mapped text remains unhighlighted.
   - Colors remain stable for existing nodeIds where possible across re-parses.

2. **Text Still Editable**
   - The underlying `textarea` remains focusable and editable at all times in “editor with highlights” mode.
   - Cursoring, selecting, and typing in the `textarea` updates the parsed overlay on debounce without UI glitching or blocking interactions.

3. **Inline Toolbar Above Text**
   - An inline toolbar (positioned above the text area) provides at least: Undo, Redo, Split at Cursor, Split Selection (creates a new mapping via a modal and tri-splits when selection is within an existing mapping).
   - Buttons are disabled/enabled based on available actions.
   - Toolbar remains visible and clickable, with appropriate z-index, in all states.

4. **Consolidation of Chiclet/Segment Editor Functionality Into One Primary View**
   - Clicking a highlighted segment shows an inline menu over the text with: Delete mapping, and Node type switcher (Text, Choice, Variable).
   - The inline menu appears only for the active/selected segment; it is rendered opaque over text with pointer events enabled and does not allow the underlying text to intercept clicks.
   - Node type switch updates analysis in place and the overlay immediately reflects the new type.

5. **Delete Mapping Behavior**
   - Clicking “Delete” removes the node mapping and node; the underlying text remains intact as plain, unhighlighted text.
   - Deleting in the middle recomputes neighboring plain segments as needed without index drift; perform a light re-parse to merge adjacent plain text.

6. **Edit Mode Toggle (Full Text Edit)**
   - An “Edit” button (bottom-right of the prompt panel) switches to a “standard text editing mode” that hides the highlight overlay and inline controls.
   - Edit Mode shows OK ("Apply Changes") and Cancel ("Discard") in a bottom bar (Esc: Cancel, Enter: OK).
   - Cancel returns to previous analysis with no reconciliation, preserving scroll/focus. OK reconciles the edited text and updates nodes, mappings, and colors.

7. **Reconciliation on OK (Diff + Best-Match Remap)**
   - On OK from Edit Mode, attempt to match existing nodes to the new text using a best-effort heuristic (e.g., LCS >70% similarity + relative ordering).
   - Preserve nodeIds/types/colors for matched segments (target ~80% retention on minor edits).
   - Generate new nodeIds for unmatched segments; remove nodes that cannot be matched.
   - Produce an updated `PromptAnalysis` ordered by position, keeping `Output` node last; emit via `onAnalysisComplete(updated)`.

8. **Overlay Interaction and Accessibility**
   - Plain overlay spans use `pointer-events: none`; inline menus use `pointer-events: auto` and sufficient z-index to be fully clickable.
   - Inline menu buttons have accessible labels/titles and are keyboard-focusable.
   - Maintain legible text color/contrast and selection with highlights active (aim WCAG 2.1 AA).

9. **Performance and Stability**
   - Debounced parsing and rendering complete within 300ms for prompts up to 2–3k characters on standard dev machines (aim <500ms on low-spec/mobile).
   - Undo/Redo works across split, mapping, and type changes.
   - No console errors; debug logs are useful but not noisy.

10. **Visual Consistency**
    - Use the existing highlight palette from `PromptDissector` / `SegmentMarker`.
    - Inline menus are opaque over text and do not flicker during scroll/edit.

11. **Removal of Separate Chiclet Mode**
    - The prior chiclet/pill segmented view is functionally replaced by the consolidated primary view. All prior useful actions (delete, type switch) exist inline.

12. **QA Validation**
    - Manual: Paste the octopus sample; verify colors, splits, type changes, delete behavior, Edit Mode flow, reconciliation (~80% retention on minor edits).
    - Node/mapping counts reflect overlay; changes propagate via `onAnalysisComplete`.
    - Edge cases: Multi-segment splits, parse failures (toast: "Parsing incomplete — edit manually?"), long prompts (no lag).

## Tasks / Subtasks

- **UI Layer**
  - Update `client/src/components/LaunchScreen/PromptDissector.tsx`:
    - Inline toolbar (Undo/Redo/Split at Cursor/Split Selection) with stable z-index and pointer events.
    - Add “Edit” button to toggle Edit Mode; hide overlay/inline controls in Edit Mode.
    - Ensure plain highlights do not block typing; menus are clickable.
  - Extend `client/src/components/LaunchScreen/SegmentMarker.tsx`:
    - Add Delete action to inline menu next to T/C/V.
    - Confirm `onChangeNodeType` updates analysis; add `onDelete` to remove mapping/node.
    - Ensure menu opacity, z-index, keyboard focus, and titles/aria-labels.

- **Logic Layer**
  - Create `client/src/lib/analysisReconciler.ts`:
    - Heuristic matching (LCS + relative order; threshold ~0.7), preserve IDs/types/colors where matched.
    - Return updated `{ nodes, mappings }` and keep Output last; unit tests for insert/delete/split/merge/large rewrite.
  - Update `client/src/lib/simplePromptParser.ts`:
    - Light re-parse on delete to merge adjacent plain ranges without index issues.

- **Styles**
  - Update `client/src/components/LaunchScreen/PromptDissector.css` and `client/src/components/LaunchScreen/SegmentMarker.css` for opacity/z-index, contrast, menu hit areas, focus rings.

- **State/Events**
  - Ensure `onAnalysisComplete` fires after split/delete/type changes and after Edit Mode OK.
  - Maintain undo/redo stacks consistently for mapping changes.
