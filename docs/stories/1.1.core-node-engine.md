# Story 1.1: Core Node Engine & File Format

## Status
Approved

## Story
**As a** developer,  
**I want** to implement the foundational node system with inline-editable data structures,  
**so that** all subsequent features can support direct graph manipulation.

## Acceptance Criteria
1. Define .psg file format schema supporting inline editing state
2. Implement base node classes with editable properties:
   - TextBlock: inline text field
   - WeightedChoice: inline sliders + text
   - Concat: inline separator field
   - Variable: inline name/value fields
3. Create deterministic execution engine with seedable random
4. Node data structure supports edit states (editing/locked/preview)
5. Validate graph execution with unit tests
6. Ensure medieval demo nodes support inline editing

## Dev Notes
### Architecture Context
- This is a complete rebuild, not an enhancement of existing code
- The current system has TypeScript issues that we're avoiding by starting fresh
- Focus on clean, type-safe implementation from the start
- Each node type must implement the EditableNode interface

### Technical Implementation Details
```typescript
interface EditableNode {
  id: string;
  type: NodeType;
  data: {
    value: any;
    isEditing: boolean;
    editBuffer: any;
    validationState: ValidationResult;
  };
  
  // Methods
  enterEditMode(): void;
  exitEditMode(save: boolean): void;
  updateEditBuffer(value: any): void;
  validate(): ValidationResult;
  renderInlineEditor(): ReactElement;
}
```

### File Structure
- Core node engine: `packages/core/runtime/`
- Node implementations: `packages/core/runtime/nodes/`
- File format schemas: `packages/core/schemas/`
- Tests: `packages/core/__tests__/`

### Integration Points
- React Flow will consume these node components
- Execution engine must integrate with preview system
- File format must support future ComfyUI export

### Performance Requirements
- Graph with 100 nodes should execute in <50ms
- Inline editing should have <100ms response time
- Use memoization where appropriate

### Rollback Procedures
1. **Feature Flag Rollback**: All new node types behind feature flag `new-core-engine`
2. **Code Rollback**: Git revert to previous commit if critical issues
3. **Data Rollback**: N/A - no data migration in this story
4. **Emergency Procedure**: 
   - Disable feature flag immediately
   - Route traffic to legacy engine endpoints
   - Notify team via Slack #emergency channel
5. **Validation**: Run existing test suite to confirm legacy functionality intact

## Testing
### Testing Standards
- Use Jest with ts-jest for unit tests
- Test files located adjacent to source files with `.test.ts` suffix
- Aim for 80% coverage minimum, 90% for core engine files
- Use snapshot testing for deterministic output validation
- Mock external dependencies appropriately

### Specific Testing Requirements
- Each node type needs comprehensive unit tests
- Graph execution needs integration tests with various topologies
- Determinism must be validated across multiple seeds
- Edit state transitions need state machine testing
- Performance benchmarks for execution time

### Success Metrics
- 100% deterministic execution (same seed = same output across 1000 runs)
- Graph execution performance: <50ms for 100 nodes
- Memory usage: <100MB for 500-node graph
- Zero TypeScript errors in core engine
- 90%+ test coverage for all node types
- File format backward compatibility maintained
