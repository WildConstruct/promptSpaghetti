# Story 1.5: Variable Node as Three-Handle Data Hub

## Status
Draft - Ready for Review

## Story
**As a** prompt author building world-aware virtual background systems,
**I want** the Variable node to have three connection handles that allow it to merge data from external sources with prompt flow,
**so that** world model data can be injected into prompts dynamically, enabling reactive extras and context-aware content generation for demos and production pipelines.

## Business Value
- **Fundraising Demo Power**: Shows evolution from static text randomizer to dynamic data-aware system
- **Clear Differentiation**: Positions tool as bridge between world simulation and prompt generation
- **Scalable Architecture**: Foundation for reactive extras responding to world events (gunfire, explosions, weather)
- **Future Integration Ready**: Clean interface for connecting any external data source

## Core Concept
Transform the Variable node from a simple getter/setter into a **data hub** with three distinct connection points:
- **Input** (left): Receives prompt text or values from upstream nodes
- **Output** (right): Passes resolved value to downstream nodes  
- **Data Inlet** (bottom): Accepts external data injection from future data nodes

This makes the Variable node the **gateway** where world model information enters the prompt graph.

## Acceptance Criteria

### 1. Three-Handle Visual Architecture
- Variable node renders with three connection handles:
  - **Left handle** (target): Standard input from graph flow
  - **Right handle** (source): Standard output to graph flow
  - **Bottom handle** (target): Data inlet for external injection
- Each handle has distinct visual styling (color/icon) for clarity
- Handles use React Flow's connection system with proper validation
- Node shows visual indicator when data inlet is connected (glow/badge)

### 2. Data Resolution Priority
- Value resolution follows clear hierarchy:
  1. **Data inlet** (if connected and has value)
  2. **Input connection** (if connected and has value)
  3. **Current value** (if set in node configuration)
  4. **Default value** (fallback)
- Resolution logic is transparent and debuggable
- Empty/null data doesn't break the flow (graceful fallback)

### 3. Variable as Template Placeholder
- Variable name defines the placeholder in text: `{variableName}`
- Supports dot notation for nested data: `{world.event}`, `{location.type}`
- Variables in connected TextBlock nodes get replaced during execution
- Multiple variables can reference the same data source

### 4. Data Injection Interface
- Data inlet accepts any JSON-serializable value:
  - Strings: `"urban environment"`
  - Numbers: `75` (intensity level)
  - Objects: `{event: "explosion", radius: 50}`
  - Arrays: `["running", "ducking", "covering"]`
- Data structure is preserved through the node
- Type validation optional but configurable

### 5. Simple Merge Behavior
- When both input and data are present:
  - **Override mode** (default): Data inlet completely replaces input
  - **Template mode**: Input acts as template, data fills placeholders
  - **Append mode**: Combines both values (for arrays/strings)
- Merge strategy configurable in node inspector
- Clear visual indication of active merge mode

### 6. Demo Scenario Support
- Mock data injection for fundraising demos:
  ```json
  {
    "event": "gunfire",
    "intensity": 8,
    "proximity": "close",
    "reaction": "panic"
  }
  ```
- Variables automatically update when data changes
- Downstream nodes re-execute with new values
- Visual feedback shows data flow through graph

### 7. Inspector Panel Integration  
- Inspector shows:
  - Current resolved value
  - Data source (inlet/input/default)
  - Connection status for each handle
  - Merge mode selector
  - Preview of how variable appears in text
- Live updates as data flows through
- Test data injection button for demos

### 8. Backwards Compatibility
- Existing Variable nodes continue to work without data inlet
- Two-handle mode still available (legacy)
- Automatic migration adds third handle to existing graphs
- No breaking changes to current functionality

### 9. Error Handling & Edge Cases
- **Data Conflicts**: When multiple variables reference same data source:
  - Warning indicator in UI with tooltip explanation
  - Fallback to last successfully resolved value
  - Debug log shows conflict resolution path
- **Malformed Data**: Invalid JSON or incompatible types:
  - Toast notification: "Data injection failed—using fallback value"
  - Error state visual on data inlet handle (red glow)
  - Graceful degradation to input/default values
- **Circular Dependencies**: Variables referencing each other:
  - Detection algorithm prevents infinite loops
  - Maximum resolution depth of 10 levels
  - Clear error message identifying the cycle

### 10. Performance & Stress Testing
- **Baseline Performance**: 
  - <100ms connection time for data inlet
  - <10ms resolution per variable
- **Scale Testing**:
  - Support 100+ variables with 1KB data payloads each
  - Maintain <500ms total graph resolution with 100 variables
  - Memory usage <50MB for large virtual crowd scenarios
- **Stress Scenarios**:
  - Rapid data updates (10Hz) remain responsive
  - 1000 extras with unique variable states
  - Network latency simulation for remote data sources

### 11. User Onboarding & Discovery
- **First-Use Tutorial**:
  - Tooltip on hover: "Connect data here for world-aware prompts"
  - Animated hint showing data flow on first connection
  - Quick-start template: "Reactive Character Example"
- **Interactive Documentation**:
  - In-app example graphs with sample data
  - Step-by-step guide in inspector panel
  - Video preview of data injection in action
- **Visual Clarity**:
  - Data inlet handle uses distinct green color
  - Connection lines animate to show data flow direction
  - Status badges: "Data Connected", "Using Fallback"

### 12. SAG-Forward Metadata & Audit Trail
- **Data Source Transparency**:
  - Every data injection logged with timestamp and source
  - Metadata includes: `{source: "world_model_v2", timestamp: 1234567890, consent: true}`
  - Export audit trail for production accountability
- **Consent Tracking**:
  - Optional consent flag in data payloads
  - Visual indicator for ethically-sourced data
  - Compliance mode restricts non-consented data usage
- **Creative Attribution**:
  - Variable resolution history preserved
  - Chain of transformations documented
  - Support for rights management metadata

## Technical Approach

### Node Structure Update
```typescript
// Extend existing VariableNode
class VariableNode {
  handles = {
    input: { type: 'target', position: 'left' },
    output: { type: 'source', position: 'right' },
    dataInlet: { type: 'target', position: 'bottom' } // NEW
  };
  
  // Resolution with data priority
  resolve(context) {
    if (this.dataInlet.hasValue()) {
      return this.mergeData(this.dataInlet.value, this.input.value);
    }
    return this.input.value || this.config.defaultValue;
  }
}
```

### React Flow Integration
```typescript
// Node renderer shows three handles

<Handle type="source" position={Position.Right} id="output" />

        style={{background: '#00ff00'}} /> {/* Green for data */}
```

## Risks & Mitigations
- **Risk**: Users confused by third handle
  - **Mitigation**: Clear visual design, tooltips, documentation
- **Risk**: Data type mismatches
  - **Mitigation**: Graceful fallbacks, type coercion, validation warnings
- **Risk**: Performance with many data connections
  - **Mitigation**: Debounced updates, efficient change detection
