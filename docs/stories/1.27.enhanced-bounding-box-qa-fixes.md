8. The bounding box must properly hide/show contained nodes when collapsed/expanded

### Architectural Concerns

1. **Component Complexity** (lines 52-1006):
   - 1000+ line component violates single responsibility principle
   - Should be refactored into smaller sub-components:
     - `BoundingBoxHeader` (title, lock, collapse controls)
     - `ResizeHandles` (resize handle rendering and logic)
     - `PortSystem` (port detection and rendering)
     - `NodeContainment` (contained node detection logic)

2. **Performance Optimization Missing**:
   - No integration with Story 0.1 performance infrastructure
   - `getContainedNodes()` called on every render without memoization
   - Missing cache for expensive calculations (bounds, containment checks)

3. **Inline Styles vs CSS**:
   - Mixed approach with both inline styles and CSS file
   - Consider consolidating to one approach for maintainability
   - CSS file exists but component uses mostly inline styles

### Code Issues Found

1. **Console Logs in Production** (lines 116, 247, 267, 319):
   ```typescript
   console.log(`[BoundingBox ${id}] Found ${contained.length} contained nodes...`);
   ```
   - Should use proper logging utility or remove for production

2. **Magic Numbers** (lines 42-47):
   ```typescript
   const COLLAPSED_HEIGHT = 90;
   const COLLAPSED_WIDTH = 280;
   ```
   - Consider extracting to configuration object or props

3. **Complex Nested Ternaries** (lines 785-837):
   - Collapsed state indicator rendering is hard to read
   - Extract to separate component or function

1. **Unnecessary Re-renders**:
