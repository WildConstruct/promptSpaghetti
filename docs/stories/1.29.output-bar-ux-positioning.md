# Story 1.29: Output Bar UX and DOM Positioning Fix

## Status
Draft

## Story
**As a** user interacting with the graph editor,
**I want** the output bar to have proper minimize/maximize behavior and not interfere with canvas interactions,
**so that** I can effectively view outputs without the UI blocking my work or behaving unpredictably

## Acceptance Criteria
1. The output bar must be a sibling of the main canvas, not a child
2. The minimize button must toggle between minimized and restored states consistently
3. The maximize button must expand to the correct height in one click
4. The output bar must not interfere with canvas interactions when overlaying
5. The output bar must remember its previous height when restored from minimized state
6. The output bar must have smooth, predictable animations for all state changes
7. Click events must not propagate through the output bar to the canvas behind
8. The output bar must be properly positioned in the z-index hierarchy

### Current Issues
- PreviewTray is currently rendered within Epic1GraphEditor but uses `position: fixed` which can cause z-index conflicts
- Minimize button minimizes but doesn't properly restore
- Maximize button requires two clicks: first goes too high, second adjusts to correct height
- The bar interferes with canvas interactions when overlaid
- No state persistence for bar position/size

### Technical Considerations
**DOM Structure Change:**
```jsx

  <div className="epic1-graph-editor">
```
