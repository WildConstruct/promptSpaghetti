# Story 1.27: node-grouping-hierarchy

## Status
Approved

## Story
**As a** graph designer,
**I want** to group related nodes together into collapsible hierarchies,
**so that** I can simplify complex graphs and focus on specific sections.

## Acceptance Criteria
1) Group Creation
- A1. Select multiple nodes + press Cmd/Ctrl+G to group
- A2. Right-click selected nodes shows "Group" option
- A3. Groups get auto-generated names (Group 1, Group 2...)
- A4. Group name is editable inline

2) Group Visualization
- B1. Grouped nodes show visual border/background
- B2. Group header shows name and node count
- B3. Collapse button in group header
- B4. Collapsed groups show as single node
- B5. Different visual style for nested groups

3) Group Behavior
- C1. Move group moves all contained nodes
- C2. Delete group has option to delete contents or ungroup
- C3. Copy/paste group preserves structure
- C4. Drag node into/out of group updates membership
- C5. Groups can be nested (max depth: 3)

4) Persistence & State
- D1. Group structure saves with graph
- D2. Collapse state persists across sessions
- D3. Group metadata (color, description) saved
- D4. Import/export preserves groups

5) Performance Requirements (Story 0.1 Integration)
- E1. Group creation/deletion <50ms for up to 100 nodes
- E2. Group toggle (collapse/expand) <30ms with caching
- E3. Maintain 60fps during group drag operations
- E4. Cache hit ratio >85% for repeated group operations
- E5. Memory usage <50MB additional for 100 groups
- E6. Worker utilization for operations >50 nodes

```typescript
import { cache, workerPool, perfMonitor } from '../performance/infrastructure';

// Create group from selected nodes - CACHED
export async function createGroup(
  selectedNodeIds: string[],
  existingGroups: Map<string, NodeGroup>
): NodeGroup {
  // Check for existing group membership
  const parentGroups = getParentGroups(selectedNodeIds, existingGroups)
  
  if (parentGroups.size > 1) {
    throw new Error('Cannot group nodes from different groups')
  }
  
  const group: NodeGroup = {
    id: generateGroupId(),
    name: `Group ${existingGroups.size + 1}`,
    nodeIds: selectedNodeIds,
    collapsed: false,
    parentGroupId: parentGroups.values().next().value,
    metadata: {
      createdAt: Date.now(),
      updatedAt: Date.now()
    }
  }
  
  return group
}

// Calculate group bounds - CACHED & OPTIMIZED
export async function getGroupBounds(
  group: NodeGroup,
  nodes: Node[]
): Promise<Bounds> {
  const cacheKey = `group:bounds:${group.id}:${group.nodeIds.join(',')}`;
  
  // Check cache first
  const cached = await cache.get(cacheKey);
  if (cached) return cached;
  
  // Large groups use worker pool
  if (group.nodeIds.length > 50) {
    const bounds = await workerPool.execute({
      type: 'CALCULATE_GROUP_BOUNDS',
      data: { group, nodes }
    });
    await cache.set(cacheKey, bounds, { ttl: 60000 });
    return bounds;
  }
  
  // Small groups calculate inline
  const groupNodes = nodes.filter(n => group.nodeIds.includes(n.id));
  if (groupNodes.length === 0) {
    return { x: 0, y: 0, width: 0, height: 0 };
  }
  
  const xs = groupNodes.map(n => n.position.x);
  const ys = groupNodes.map(n => n.position.y);
  const rights = groupNodes.map(n => n.position.x + (n.width || 150));
  const bottoms = groupNodes.map(n => n.position.y + (n.height || 50));
  
  const bounds = {
    x: Math.min(...xs) - 20,
    y: Math.min(...ys) - 40,
    width: Math.max(...rights) - Math.min(...xs) + 40,
    height: Math.max(...bottoms) - Math.min(...ys) + 60
  };
  
  await cache.set(cacheKey, bounds, { ttl: 60000 });
  return bounds;
}

// Collapse group to single node
export function collapseGroup(
  group: NodeGroup,
  nodes: Node[]
): Node {
  const bounds = getGroupBounds(group, nodes)
  
  return {
    id: `group-${group.id}`,
    type: 'groupNode',
    position: { x: bounds.x, y: bounds.y },
    data: {
      group,
      nodes: nodes.filter(n => group.nodeIds.includes(n.id))
    },
    style: {
      width: Math.min(bounds.width, 300),
      height: 80
    }
  }
}
```

```typescript
// Custom hook for group-aware node rendering
export function useGroupedNodes(nodes: Node[], groups: Map<string, NodeGroup>) {
  return useMemo(() => {
    const visibleNodes: Node[] = []
    const hiddenNodeIds = new Set<string>()
    
    // Find collapsed groups and their nodes
    groups.forEach(group => {
      if (group.collapsed) {
        group.nodeIds.forEach(id => hiddenNodeIds.add(id))
        visibleNodes.push(collapseGroup(group, nodes))
      }
    })
    
    // Add non-hidden nodes
    nodes.forEach(node => {
      if (!hiddenNodeIds.has(node.id)) {
        visibleNodes.push(node)
      }
    })
    
    return visibleNodes
  }, [nodes, groups])
}
```

**Reviewer:** Quinn (Senior Developer & QA Architect) 🧪

#### Story Assessment
**Readiness Score: 7.8/10**

##### Strengths:
1. **Clear Functionality**: Group creation and management well-defined
2. **Good UX Design**: Keyboard shortcuts and visual feedback specified
3. **Nesting Support**: Hierarchical grouping with depth limits
4. **State Management**: Collapse state persistence considered

##### Critical Architectural Concerns:
1. **State Complexity**: 
   - Nested groups create complex state trees
   - Need robust state normalization strategy
   - Consider using state machines for group operations

2. **React Flow Integration Challenges**:
   ```typescript
   // This approach has issues with React Flow's internal state
   // Better approach: Use React Flow's built-in grouping
   import { useReactFlow } from 'reactflow';
   
   const { getNodes, setNodes } = useReactFlow();
   // Manipulate nodes array directly for grouping
   ```

3. **Performance Risks**:
   - Recursive operations on nested groups
   - Large collapsed groups still in memory
   - Edge recalculation overhead

##### Refactoring Suggestions:

1. **Simplified Group Model**:
   ```typescript
   interface NodeGroup {
     id: string
     name: string
     nodeIds: Set<string> // Use Set for O(1) lookups
     parentId?: string
     collapsed: boolean
     // Remove position - calculate dynamically
   }
   
   // Separate presentation from data
   interface GroupPresentation {
     bounds: DOMRect
     style: GroupStyle
   }
   ```

2. **State Normalization**:
   ```typescript
   interface NormalizedGroupState {
     byId: Record<string, NodeGroup>
     allIds: string[]
     nodeToGroup: Record<string, string>
     rootGroups: string[] // Top-level groups
   }
   ```

3. **Performance Optimizations**:
   - Use virtual rendering for collapsed groups
   - Lazy-load group contents on expand
   - Implement group operation batching

##### Implementation Risks:
1. **Edge Rendering**: Edges to/from grouped nodes need special handling
2. **Undo/Redo**: Complex state changes need careful transaction design
3. **Copy/Paste**: Deep cloning of nested structures
4. **Circular Dependencies**: Parent-child relationship validation

##### Testing Requirements:
1. Stress test with 50+ groups, 3 levels deep
2. Test group operations on 1000+ node graphs
3. Memory profiling for collapsed groups
4. Edge case: Moving nodes between groups
5. Concurrent group operations (multi-select)

##### Alternative Approach:
Consider using React Flow's SubFlow feature instead of custom grouping:
- Better performance
- Native support
- Simpler state management

**Verdict: Needs architecture review before implementation. Consider simpler alternatives.** ⚠️

**Recommendation**: Schedule technical spike to evaluate React Flow SubFlow vs custom implementation
