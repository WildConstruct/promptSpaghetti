# Story 20.2: Internal File Browser & Project Management

## Status
Draft

## Story
**As a** user of the prompt-spaghetti application,
**I want** an integrated file browser system for managing .psg files and project organization,
**so that** I can efficiently create, organize, navigate, and manage my prompt generation projects with seamless integration to the graph editor.

## Acceptance Criteria

1. **File Browser UI Component**: Create a dedicated file browser interface that displays .psg files in a tree structure with folders, subfolders, and file organization capabilities

2. **Authentication Integration**: File browser integrates with the authentication system from Story 20.1, respecting user permissions and showing only accessible files/projects

3. **Core File Operations**: Support essential file operations including upload, download, rename, delete, duplicate, and move operations with proper confirmation dialogs

4. **Project Management Structure**: Implement hierarchical project organization with the ability to create nested folders, tag files, and maintain project metadata

5. **Graph Editor Integration**: Seamless transition between file browser and graph editor, with the ability to open .psg files directly in the editor and save changes back to the file system

6. **Search and Filtering**: Advanced search capabilities including filename search, content search within .psg files, date filters, and tag-based filtering

7. **File Preview System**: Quick preview functionality for .psg files showing graph thumbnails, node counts, and basic metadata without fully opening the editor

8. **Collaborative Features**: Multi-user support with file locking, sharing permissions, and conflict resolution when multiple users access the same project

9. **Import/Export Workflows**: Bulk import/export capabilities for project migration, backup creation, and external integrations

10. **Recent Files & Favorites**: Quick access to recently accessed files and user-marked favorites with persistent storage

### Architecture Integration Points

**Frontend Structure:**
- FileBrowser component integrates with existing `/client/src/components/` structure
- Uses established Zustand patterns following graphStore.ts architecture
- Leverages React Router integration from Story 20.1 for navigation
- Integrates with existing authentication system and permissions

**Backend Integration:**
- File storage API extends `/server/src/routes/` with new file management endpoints
- Leverages existing authentication middleware and session management
- Uses established database patterns from `/server/src/database/` for metadata storage
- Integrates with existing audit logging and security systems

### File System Architecture

**Storage Strategy:**
- .psg files stored in organized directory structure on server filesystem

- File thumbnails and previews cached for performance optimization
- Implement proper backup and disaster recovery procedures

**Security Considerations:**

### Database Schema Extensions

**New Tables Required:**
```sql
-- Project metadata and organization
projects (id, name, description, owner_id, created_at, updated_at, tags)
project_permissions (project_id, user_id, permission_level)
project_files (id, project_id, filename, file_path, size, created_at)
file_metadata (file_id, node_count, complexity_score, thumbnail_path)
recent_files (user_id, file_id, accessed_at)
user_favorites (user_id, file_id, created_at)
```

### API Endpoints Design

**File Management Endpoints:**
- `GET /api/files` - List files with filtering and pagination
- `POST /api/files/upload` - File upload with validation
- `PUT /api/files/:id` - Update file metadata and content
- `DELETE /api/files/:id` - Delete file with proper authorization
- `GET /api/files/:id/preview` - Generate file preview/thumbnail
- `POST /api/projects` - Create new project/folder
- `GET /api/search/files` - Advanced file search functionality
