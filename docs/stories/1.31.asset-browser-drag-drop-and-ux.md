# Story 1.31: Asset Browser Drag-and-Drop & UX polish

## Status
InProgress

## Story
As a graph editor user,
I want to drag presets from the Asset Browser and drop them into the canvas,
so that I can quickly compose graphs from reusable building blocks.

## Acceptance Criteria
1. Dragging a preset from `packages/asset-browser/src/components/ProAssetBrowser.tsx` (and `PresetCard`) sets HTML5 drag payload with MIME `application/x-preset` and JSON containing `{ id, name, tags, type }`. When available from manifest, include `path` and/or `psgContent`.
2. `packages/core/components/epic1/Epic1GraphEditor.tsx` `onDrop` recognizes `application/x-preset`, prevents default, converts screen coords to graph coords using the current ReactFlow viewport transform, and inserts via `insertPresetFromDrop(psglibContent, graphPos, viewportTransform)`.
3. Preset content resolution order:
   - Inline `psgContent` (if present) → validate against `docs/psg-format-v2.md` and convert for insertion if needed.
   - `path` → load via `loadPresetFromPath(path)`.
   - `id` → resolve to path/content using manifest or `LibraryService` mapping.
4. All included presets conform to PSG v2 format (`.psg`, `application/x-promptspaghetti-graph`) per `docs/psg-format-v2.md`. Loader validates with `psgSchemaV2`. If insertion path requires PSGLib, convert PSG→PSGLib internally before calling `insertPreset`.
5. Successful preset insertion adds nodes, snaps to grid, selects inserted nodes, and shows a success toast with preset name. No regressions to other drag types (`application/reactflow`, `application/node-type`, `text/plain`).
6. Asset Browser UX updates:
   - Remove duplicate Library/Server segmented control at the top of the panel.
   - Keep/use the inline Library/Server control; position it above the keywords area.
   - Render keywords as wrapped button chips (multi-row) instead of a long vertical list. Clicking toggles the filter state (active/inactive) with clear visual affordance.
   - When a preset is selected (click), show a preview panel at the bottom: name, category, tags, brief description/summary, node count (if available), and thumbnail if provided by metadata.
7. `packages/core/components/epic1/AssetBrowserLoader.tsx` forwards `onInsert(preset)` without incorrect guards; insert from button/double-click uses same insertion flow as drop, with default position at viewport center.
8. Tests cover: drag payload shape, drop handling, coordinate conversion, content resolution branches, node insertion side effects, toast display, `onInsert` forwarding, and UX changes (segmented control, keyword buttons, preview panel visibility and content).
9. Accessibility: keyword buttons and controls are keyboard accessible (tab/enter/space), drag handle has appropriate a11y labels, and preview content is reachable and labeled.
