# Story 1.12: open-dialog-supabase-tab

## Status
Complete

## Story
**As a** signed-in user,
**I want** a Supabase tab in Open dialog showing my saved graphs,
**so that** I can reopen my `.psg` files stored in the cloud.

## Acceptance Criteria
1) Gating
- A1. Supabase tab is visible only when client configured and `userId` available.
- A2. When hidden, no network calls are made for Supabase.

2) Listing
- B1. The tab lists user `.psg` files from `listUserGraphs` with name and updatedAt (if available).
- B2. Loading indicator appears while listing; empty state appears when none.

3) Open flow
- C1. Selecting a file fetches content via `getUserGraph`, parses with codec, and opens it.
- C2. Errors in fetch or parse show a friendly message with a retry.

4) Error/Empty
- D1. Distinct UI for Empty vs Error; telemetry hook optional.

## Dev Notes
- Requires a userId provider; acceptable to stub minimal auth in this story or rely on a mock provider.

 - Reuse shared `EmptyState`/`ErrorState` components from Story 1.15.

### Implementation Summary
- Component: `packages/asset-browser/src/components/OpenGraphDialog.tsx` with a dedicated Supabase pane.
- Gating: Supabase tab renders only when `enableSupabase && userId && supabaseList && supabaseGet`.
- Helpers: Injected via props to avoid cross-package imports and ease testing. Signatures align with core utils `psgStorage.ts` discriminated results.
- States: Distinct loading, empty, success, and error. Errors surface as alerts with `role="alert"` for accessibility.
 - Note (Story 1.14+): `OpenGraphDialog` will read `userId` from `UserProvider` context if the prop is not provided.
- Accessibility: Clear semantics for tab, lists, and alerts; keyboard navigation supported.

### Wiring Notes (App Integration)
Import from `asset-browser` and wire real helpers from `core/utils`:

```tsx
import React from 'react';
import { OpenGraphDialog } from '@prompt/asset-browser';
import { listUserGraphs, getUserGraph } from '@prompt/core/utils';

export function OpenDialogContainer({ userId }: { userId?: string }) {
  const [open, setOpen] = React.useState(false);
  const enableSupabase = Boolean(
    process.env.NEXT_PUBLIC_SUPABASE_URL || process.env.VITE_SUPABASE_URL
  ) && Boolean(
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY || process.env.VITE_SUPABASE_ANON_KEY
  );

  return (
    <>
      <button onClick={() => setOpen(true)}>Open…</button>
      <OpenGraphDialog
        isOpen={open}
        onClose={() => setOpen(false)}
        onOpenGraph={(graph) => {/* consume parsed graph */}}
        userId={userId}
        enableSupabase={enableSupabase}
        supabaseList={listUserGraphs}
        supabaseGet={getUserGraph}
      />
    </>
  );
}
```

#### Context Fallback (Story 1.14+)
If your app is wrapped with `UserProvider`, you can omit the `userId` prop and let the dialog read it from context:

```tsx
import React from 'react';
import { UserProvider, OpenGraphDialog } from '@prompt/asset-browser';
import { listUserGraphs, getUserGraph } from '@prompt/core/utils';

const enableSupabase = Boolean(
  process.env.NEXT_PUBLIC_SUPABASE_URL || process.env.VITE_SUPABASE_URL
) && Boolean(
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY || process.env.VITE_SUPABASE_ANON_KEY
);

export function OpenDialogContainerWithContext({ supabase }: { supabase?: any }) {
  return (
    <UserProvider supabase={supabase}>
      <OpenGraphDialog
        isOpen
        onClose={() => {}}
        onOpenGraph={(graph) => {/* consume parsed graph */}}
        enableSupabase={enableSupabase}
        supabaseList={listUserGraphs}
        supabaseGet={getUserGraph}
      />
    </UserProvider>
  );
}
```

### Environment Variables
- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (Next.js) or
- `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (Vite)

When missing, the core client exports `null` and the UI will gate off the Supabase tab.
