## Story
**As a** prompt author working with the node graph,
**I want** core intelligent assistance features for populating choices and optimizing weights,
**so that** I can quickly generate rich variations and optimal distributions without manual brainstorming.

## Business Value
- **Demo Magic**: "Populate Choices" creates instant investor "wow" 
- **MVP Focus**: Essential features only for fundraising demos
- **Quick Wins**: Immediately visible value in <2 weeks development
- **Risk Reduction**: Smaller scope ensures on-time delivery

## Acceptance Criteria

### 1. Populate Choices for WeightedChoice Nodes
- Add "Populate Choices" button in WeightedChoice inspector panel
- Button appears when node has <3 choices or on new nodes
- On click:
  - Analyze segment text and full prompt context
  - Generate 5-10 contextually relevant variations
  - Auto-assign weights based on likelihood/appropriateness
- Display loading spinner during generation (~1-2 seconds)
- Results appear as editable choices user can modify/delete
- Handle errors gracefully with fallback to empty suggestions
- Example:
  ```
  Input: "drifting car"
  Output: [
    {"text": "aggressively sliding sideways", "weight": 8},
    {"text": "controlled power slide", "weight": 7},
    {"text": "spinning out dramatically", "weight": 4},
    {"text": "smoothly drifting around corner", "weight": 6},
    {"text": "tire-smoking slide", "weight": 5}
  ]
  ```

### 2. Optimize Weights Based on Context
- Add "Optimize Weights" button next to existing choices
- Analyzes:
  - Choice relevance to prompt context
  - Desired variation distribution
  - Semantic similarity between choices
- Suggests new weight values (1-10 scale)
- Shows before/after preview
- One-click apply or manual adjustment
- Maintains user overrides as "locked" weights
- Handles invalid responses with original weights retained

### 3. Inspiration Mode for Empty Nodes
- Empty WeightedChoice nodes show "Need inspiration?" prompt
- Analyzes upstream context
- Suggests 3 thematic directions
- One-click to populate with suggestions
- Example for "urban scene" context:
  ```
  Suggestions:
  - Crowd reactions (panic, curiosity, indifference)
  - Environmental details (debris, smoke, sirens)
  - Time variations (dawn, noon, dusk, night)
  ```

### 4. Performance & Reliability
- All operations complete in <2 seconds
- Clear loading states with cancel button
- Graceful degradation on LLM failure
- Cache suggestions for 5 minutes
- Retry logic with exponential backoff
- Fallback to static suggestions if all LLMs fail

### 5. User Control & Transparency
- Global toggle: "Enable Intelligent Assistance"
- Confidence indicators (high/medium/low) on suggestions
- Undo support for all operations
- Manual trigger only (no auto-suggestions)
- Clear indication when using cached vs fresh results
- Artist-in-the-loop overrides always respected
- Director-first: All suggestions are proposals, not mandates

### 6. Offline Fallback Mode
- Automatic detection of network/LLM unavailability
- Seamless switch to offline suggestions:
  - Pre-computed common variations by category
  - Pattern-based weight distribution
  - Context-aware template matching
- Visual indicator: "Offline Mode" badge (subtle, non-intrusive)
- Offline suggestion quality:
  - 50+ pre-computed patterns per node type
  - Covers 80% of common use cases
  - Weekly updates from aggregated usage data
- Zero functionality loss - all features remain available

### 7. Variable Preservation
- All populate/optimize operations preserve {variables}
- Variable detection before LLM call:
  ```javascript
  const variables = extractVariables(text); // [{name: 'reaction', position: 12}]
  const cleanText = removeVariables(text);
  // LLM processes clean text
  const suggestions = restoreVariables(llmOutput, variables);
  ```
- Variables maintain position and formatting
- New suggestions can include compatible variables
- Variable validation ensures type consistency

## Technical Implementation

### Focused Service Integration
```typescript
// WeightedChoiceEditor.tsx - Simplified for MVP
const handlePopulateChoices = async () => {
  setLoading(true);
  try {
    const suggestions = await llmService.populateChoices({
      segment: nodeData.text,
      context: getPromptContext(),
      count: 7
    });
    
    if (!suggestions || suggestions.length === 0) {
      // Fallback to static suggestions
      setChoices(getStaticSuggestions(nodeData.text));
    } else {
      setChoices(suggestions);
    }
  } catch (error) {
    console.error('LLM failed:', error);
    showToast('Using offline suggestions');
    setChoices(getStaticSuggestions(nodeData.text));
  } finally {
    setLoading(false);
  }
};
```

### Streamlined LLM Prompts
```javascript
// Populate Choices - Concise with guardrails
"Given '{segment}' in context '{context}', suggest 5-10 variations.
Be creative but appropriate. Avoid inappropriate content.
Output JSON only: {choices: [{text: string, weight: 1-10}]}"

// Optimize Weights - Simple and focused
"Suggest weights 1-10 for variety and relevance:
Choices: {choices}
Output JSON: {weights: [numbers]}"
```
