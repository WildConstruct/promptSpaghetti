# Story 1.13: save-to-supabase

## Status
Implemented

## Story
**As a** signed-in user,
**I want** to save the current graph to Supabase storage,
**so that** I can persist and reopen my work across devices.

## Acceptance Criteria
1) Gating
- A1. Save-to-Supabase is enabled only when client configured and `userId` present.

2) Upload behavior
- B1. Upload to `graphs` bucket under `users/{userId}/graphs/{name}.psg`.
- B2. Use `contentType: application/json` and `upsert: true`.
- B3. Validate `.psg` extension and sanitize `name` before upload.

3) Visibility
- C1. Successful saves appear in the Open dialog Supabase tab on next refresh.
- C2. Provide a way to trigger refresh or auto-refresh after save.

4) Error handling
- D1. Errors show friendly messages with retry; do not dismiss dialog automatically.

## Tasks / Subtasks
- Gating (A)
  - [x] Show/hide Supabase option based on client + userId (AC: A1). Implemented in `packages/asset-browser/src/components/SaveGraphDialog.tsx` via gated "Save to Supabase" button.
- Upload (B)
  - [x] Serialize graph (stable JSON stringify for now) and upload using injected `putUserGraph`-compatible helper (AC: B1–B2).
  - [x] Enforce `.psg` name and sanitize input (AC: B3).
- Visibility (C)
  - [x] Provide `onSupabaseSaved` callback for parent to refresh the Open dialog Supabase tab (AC: C1–C2).
- Errors (D)
  - [x] Implement retry-friendly error surface; keep dialog open (AC: D1).

## Dev Notes
- Serializer: currently uses stable `JSON.stringify(graph, null, 2)` until `psgCodec.writePsg` is available.
- Filename sanitization: allow `[A-Za-z0-9._-]`, trim, collapse spaces to `-`, max 64 chars before extension, and always ensure `.psg` extension.
- Upload options (in helper): `contentType: application/json`, `upsert: true`.
- Button gating: the Supabase button renders only when `enableSupabase && userId && supabasePut` are truthy. It remains clickable even with an invalid filename so the handler can surface validation errors.

## Usage
- Import and render `SaveGraphDialog` from `@prompt/asset-browser`.
- Inject Supabase context from the app shell:
  - `enableSupabase`: derived from env presence (e.g., Vite `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` or Next `NEXT_PUBLIC_*`).
  - `userId`: current signed-in user's id. As of Story 1.14, this can be omitted if your app is wrapped in `UserProvider` (the dialog will read from context).
  - `supabasePut`: adapter matching `putUserGraph(userId, name, content)` returning `{ ok: true, data: { path } } | { ok: false, error: { message } }`.
  - `onSupabaseSaved(name, path)`: callback to trigger an Open dialog Supabase refresh if needed.

Props added in `SaveGraphDialog`:
- `enableSupabase?: boolean`
- `userId?: string`
- `supabasePut?: (userId: string, name: string, content: string) => Promise<
  | { ok: true; data: { path: string } }
  | { ok: false; error: { message: string } }
>`
- `onSupabaseSaved?: (name: string, path?: string) => void`

Note:
- When using `UserProvider` (see Story 1.14), `SaveGraphDialog` will use the context `userId` if the prop is not provided.

## Dependencies / Risks
- Dependencies: 1.11 (storage utils), 1.12 (Open dialog integration), 1.14 (userId provider).
- Risks: Overwriting unintended files; upsert is expected but communicate clearly in UI.
