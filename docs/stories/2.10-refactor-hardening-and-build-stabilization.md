# Story 2.10: Refactor Hardening & Build Stabilization

## Status

READY TO START (Created: 2025-09-08)

## Story

As a platform team preparing an internal demo and near-term release,
I want core refactors that stabilize builds, secure LLM usage, and reduce future regressions,
So that the product remains demo-ready, safer to iterate on, and easier to maintain.

## Business Value

- Demo reliability: fast, reproducible client and server builds
- Security: no API keys in browser; LLM calls centralized server-side
- Maintainability: clearer entry points, smaller blast radius for changes
- QA velocity: fewer flaky builds and easier test targeting

## Current State Analysis

- Client build fixed via production-safe config and LLM browser adapter
- Server compile stabilized with minimal entry; legacy files contain syntax corruption
- OpenAI Node shims previously leaked into browser bundles
- Multiple editor variants exist; one (“Final”) has corrupted regions
- CORS was hardcoded for localhost; now parameterized for environments

## Acceptance Criteria

### AC1: LLM Routing & Security (Priority 0)

- [ ] Browser never bundles Node OpenAI shims (verified in prod build artifacts)
- [ ] Client LLM adapter calls server endpoints only (`/api/llm/*`)
- [ ] Server `/api/llm/complete` uses env-based keys, timeouts, and returns errors gracefully
- [ ] Basic privacy filter hook in endpoint (PII redaction scaffold; no secrets returned)
- [ ] Minimal rate limit (in-memory) caps burst and per-minute calls

### AC2: Server Build Stabilization (Priority 0)

- [ ] `server/tsconfig.json` compiles only working surfaces (index, routes, services)
- [ ] Legacy/broken files are quarantined or excluded from build
- [ ] Health, Preview, LLM endpoints pass a quick smoke (200/JSON)
- [ ] CORS controlled via `CORS_ORIGINS`; credentials allowed only for explicit origins

### AC3: Editor Hygiene (Priority 1)

- [ ] Epic1 default export is a single, compiling editor (Monolithic for now)
- [ ] Corrupted `Epic1GraphEditorFinal.tsx` cleaned or quarantined; no imports reference it
- [ ] Duplicate imports removed; stray text/escape artifacts eliminated
- [ ] Optional: restore “Final” editor in a follow-up story once cleaned and tested

### AC4: Build Config Consolidation (Priority 1)

- [ ] Merge production-safe Vite tweaks into primary config behind `BUILD_SAFE=true`
- [ ] Single source of aliases for local packages and shims
- [ ] OpenAI and LLM aliases enforced across dev/prod builds

### AC5: TypeScript Boundaries & Tests (Priority 2)

- [ ] Narrow “include” in tsconfigs for server and core subpackages
- [ ] Add tests for asset registry contract (dispatch/update) consumers
- [ ] Add unit tests for consistency strictness mapping and overlays
- [ ] Add smoke tests for LLM adapter (client → server stub/real → success path)

## Non-Goals (This Story)

- Full repair of all legacy server modules (exporters, TLS, validators)
- Large UI feature additions beyond stabilizing entry points

## Tasks

1. Harden `/api/llm/complete`
   - Add simple PII redaction (email, phone, key-like patterns)
   - Add in-memory token-bucket limiter (per-IP + per-session)
   - Timeouts/retries with clear error payloads
2. Consolidate client build configs
   - Port prod-safe aliases into main config behind `BUILD_SAFE`
   - Ensure `optimizeDeps.exclude` blocks OpenAI in browser
3. Quarantine/repair editor Final file
   - Remove references; create `epic1-final-quarantined.tsx` or fix corrupted regions
4. Server tsconfig hardening
   - Lock include globs; exclude experimental files from emission
5. Add focused tests
   - Asset registry event test (Search/Relations listeners)
   - Consistency strictness mapping unit tests
   - Client LLM adapter smoke test (mock fetch → success/error)

## Risks & Mitigations

- Risk: Hidden imports reintroduce Node shims into browser
  - Mitigation: Central alias + CI build check for forbidden modules
- Risk: Rate limiting causes false positives in demo
  - Mitigation: Wide demo thresholds + disable via env if needed
- Risk: Editor “Final” cleanup takes longer
  - Mitigation: Keep Monolithic as default until Final is verified

## Definition of Done

- Green client and server builds in CI
- Browser bundles contain no OpenAI Node shims
- LLM endpoint works with and without API key (stub fallback)
- Editor exports stable; no references to corrupted source
- New tests passing; coverage trend non-decreasing

- Parameterized CORS; added explicit origin control per environment
- Simplified server compile surface; legacy modules quarantined
