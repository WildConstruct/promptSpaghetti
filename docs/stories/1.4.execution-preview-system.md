# Story 1.4: Execution & Preview System

## Status
Approved

## Story
**As a** user,  
**I want** to see variations update live as I edit nodes inline,  
**so that** I get immediate feedback on my changes.

## Acceptance Criteria
1. Preview panel updates with 300ms debounce during editing
2. Edited node highlights which preview items changed
3. Seed control accessible without leaving edit mode
4. One-click copy from preview to clipboard
5. Visual connection between edited node and affected outputs
6. Performance: smooth updates even during rapid editing

## Dev Notes
### Architecture Context
- Critical for real-time feedback experience
- Must integrate with Story 1.1's execution engine
- Performance is paramount - any lag breaks the flow
- Consider progressive rendering for large outputs

### Technical Implementation Details
```typescript
interface PreviewSystem {
  // Debounced execution
  scheduleUpdate(graph: Graph, delay: number): void;
  
  // Change tracking
  trackChanges(previousOutputs: string[], newOutputs: string[]): ChangeSet;
  
  // Performance monitoring
  measureExecutionTime(): PerformanceMetrics;
  
  // Cache management
  getCachedResults(graph: Graph, seed: number): string[] | null;
}

interface ChangeSet {
  changedIndices: number[];
  diffs: Array<{
    index: number;
    added: string[];
    removed: string[];
  }>;
}
```

### Performance Architecture
1. **Execution Pipeline**:
   - Web Worker for graph execution
   - Main thread for UI updates only
   - Stream results as available

2. **Caching Strategy**:
   - Cache execution results by graph hash + seed
   - Invalidate cache on node edits
   - LRU eviction for memory management

3. **Rendering Optimization**:
   - Virtual scrolling for many variations
   - React.memo for variation components
   - RequestAnimationFrame for animations

### Medieval Demo Performance
- Target: 20 variations in <1 second
- Graph complexity: ~10-15 nodes
- Expected output length: 50-100 chars each
- Must feel instant during demos

### Visual Design
- Subtle animations (ease-out, 200ms)
- Color coding for change intensity
- Minimalist UI to not distract
- Focus on content, not chrome

### Rollback Procedures
1. **Feature Flag Rollback**: Live preview behind flag `live-preview-v2`
2. **Performance Fallback**: Disable live updates, require manual refresh
3. **Worker Fallback**: Execute on main thread if Worker fails
4. **Emergency Procedure**:
   - Disable real-time preview
   - Show "Generate" button instead
   - Cache last known good results
5. **Resource Protection**: Kill long-running executions after 5s
