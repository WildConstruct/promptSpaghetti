# Story 11.1: User Management Foundation

## Status

Draft

## Story

**As a** administrator of the prompt-spaghetti application,
**I want** a comprehensive user management foundation with authentication, authorization, and role-based access control,
**so that** I can securely manage multiple users, control access to features, and maintain proper security governance.

## Acceptance Criteria

1. **Authentication Foundation**: System implements secure authentication with JWT tokens, password hashing (Argon2id), session management, and support for multiple login methods (email/password, OAuth providers)

2. **User Management System**: Application provides comprehensive user CRUD operations, user profile management, account activation/deactivation, and user search/filtering capabilities with administrative interfaces

3. **Role-Based Access Control (RBAC)**: System implements flexible RBAC with customizable roles, permissions, and access control policies that can be assigned to users and enforced throughout the application

4. **Session & Security Management**: Application tracks user sessions, provides device management, implements security features (password policies, account lockout, audit logging), and maintains security event monitoring

5. **Administrative Interface**: System provides dedicated administrative dashboard for user management, role assignment, security monitoring, and system governance with proper access controls

6. **Integration & API Foundation**: User management system integrates with existing authentication components and provides secure APIs for other services with proper authentication and authorization enforcement

### Database Schema Design

**Core User Management Tables:**

```sql
-- Users table with comprehensive user information
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  first_name VARCHAR(100),
  last_name VARCHAR(100),
  avatar_url VARCHAR(500),
  status user_status DEFAULT 'active',
  email_verified BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  last_login_at TIMESTAMP,
  password_changed_at TIMESTAMP DEFAULT NOW()
);

-- Roles table for RBAC system
CREATE TABLE roles (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(100) UNIQUE NOT NULL,
  description TEXT,
  is_system_role BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- Permissions table for granular access control
CREATE TABLE permissions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(100) UNIQUE NOT NULL,
  resource VARCHAR(100) NOT NULL,
  action VARCHAR(50) NOT NULL,
  description TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

-- User role assignments
CREATE TABLE user_roles (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  role_id UUID REFERENCES roles(id) ON DELETE CASCADE,
  assigned_by UUID REFERENCES users(id),
  assigned_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(user_id, role_id)
);

-- Sessions table for session management
CREATE TABLE user_sessions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  refresh_token_hash VARCHAR(255) NOT NULL,
  device_info JSONB,
  ip_address INET,
  created_at TIMESTAMP DEFAULT NOW(),
  expires_at TIMESTAMP NOT NULL,
  last_activity TIMESTAMP DEFAULT NOW()
);
```

### Authentication & Security Implementation

**JWT Token Structure:**

```typescript
interface JWTPayload {
  sub: string; // user ID
  email: string;
  roles: string[];
  permissions: string[];
  iat: number; // issued at
  exp: number; // expiration
  iss: string; // issuer
  aud: string; // audience
}
```

**Password Security:**

- **Hashing Algorithm**: Argon2id with memory cost 19MB, time cost 2, parallelism 1
- **Salt Generation**: Cryptographically secure random salt per password
- **Password Policy**: Minimum 12 characters, mixed case, numbers, special characters
- **Breach Detection**: Integration with HaveIBeenPwned API for compromised password checking

**Session Security:**

- **Session TTL**: 24 hours with sliding window renewal
- **Device Tracking**: Fingerprinting for suspicious activity detection
- **Multi-Device Support**: Users can manage active sessions across devices
- **Automatic Cleanup**: Expired session cleanup and inactive session pruning

### RBAC System Design

**Role Hierarchy:**

```typescript
enum SystemRoles {
  SUPER_ADMIN = 'super_admin', // Full system access
  ADMIN = 'admin', // User and content management
  EDITOR = 'editor', // Content creation and editing
  VIEWER = 'viewer', // Read-only access
  GUEST = 'guest', // Limited public access
}

enum Permissions {
  // User management
  USER_CREATE = 'user:create',
  USER_READ = 'user:read',
  USER_UPDATE = 'user:update',
  USER_DELETE = 'user:delete',

  // Role management
  ROLE_CREATE = 'role:create',
  ROLE_ASSIGN = 'role:assign',

  // Graph operations
  GRAPH_CREATE = 'graph:create',
  GRAPH_EDIT = 'graph:edit',
  GRAPH_DELETE = 'graph:delete',
  GRAPH_SHARE = 'graph:share',
}
```

**Permission Checking:**

- **Context-Aware**: Permissions checked with resource context (own vs. others' content)
- **Cached Evaluation**: Redis caching for frequently checked permissions
- **Audit Trail**: All permission checks logged for security analysis
- **Dynamic Permissions**: Support for computed permissions based on context

### API Design & Documentation

**RESTful Endpoints:**

```typescript
// User Management APIs
POST /api/admin/users           // Create user
GET /api/admin/users            // List users (paginated, filtered)
GET /api/admin/users/:id        // Get user details
PUT /api/admin/users/:id        // Update user
DELETE /api/admin/users/:id     // Delete user

// Role Management APIs
POST /api/admin/roles           // Create role
GET /api/admin/roles            // List roles
PUT /api/admin/roles/:id        // Update role
POST /api/admin/users/:id/roles // Assign role to user

// Session Management APIs
GET /api/users/sessions         // List user's active sessions
DELETE /api/users/sessions/:id  // Terminate session
```

**GraphQL Schema:**

```graphql
type User {

type Mutation {
```
