# Story 2.1: Core LLM Infrastructure & OpenRouter Integration

## Status

✅ COMPLETE (2025-01-26) - Core Implementation

## Story

**As a** developer building intelligent features into the prompt randomization tool,
**I want** a robust LLM service layer that transparently integrates with OpenRouter for multi-model access,
**so that** I can add subtle intelligence features throughout the application without exposing chat interfaces or creating vendor lock-in.

## Business Value

- **Foundation for Intelligence**: Enables all subsequent LLM-powered features
- **Cost Control**: Free tier priority with automatic fallbacks to paid models
- **Vendor Flexibility**: OpenRouter provides access to 400+ models without lock-in
- **Demo Ready**: Token tracking and limits ensure predictable costs during fundraising

## Acceptance Criteria

### 1. OpenRouter Service Integration

- Create `LLMService` class in `packages/core/services/llm/`
- Configure with environment variable for API key
- Support both client-side (dev) and server proxy (production) modes
- Implement connection testing with health check endpoint
- Handle API key validation and error states

### 2. Model Selection & Fallback Chain

- Define model hierarchy with automatic fallbacks:
  ```javascript
  Primary: 'deepseek/deepseek-r1:free' (reasoning)
  Fallback1: 'mistral/mistral-medium-3.1:free' (quick tasks)
  Fallback2: 'qwen/qwen-262k:free' (long context)
  Fallback3: 'openai/gpt-4o-mini' (paid backup, $0.05/M)
  ```
- Implement automatic retry with next model on failure
- Support task-specific model selection (metadata vs generation)
- Log model usage for cost analysis

### 3. Structured Output Enforcement

- All LLM responses must return valid JSON
- Implement JSON schema validation for each call type:
  - Choice suggestions: `{choices: [{text: string, weight: number}]}`
  - Metadata: `{tags: string[], subject: string, intensity: number}`
  - Refinements: `{original: string, refined: string, changes: string[]}`
- Retry with schema correction on parse failure
- Maximum 3 retry attempts before graceful failure

### 4. Token Management & Efficiency

- Token counting before API calls (tiktoken or approximation)
- Enforce limits:
  - Input: Max 500 tokens (truncate if needed)
  - Output: Max 200 tokens via max_tokens parameter
  - Total per call: 700 tokens budget
- Implement prompt compression:
  - Remove redundant whitespace
  - Truncate context to most relevant portion
  - Use `slice(0, 500)` for long prompts

### 5. Response Caching Layer

- In-memory cache with LRU eviction (100 entry limit)
- Cache key: hash of (prompt + model + parameters)
- TTL: 15 minutes for suggestions, 60 minutes for metadata
- Skip cache option for time-sensitive calls
- Local storage persistence for development

### 6. Cost Tracking & Limits

- Track tokens per model per session
- Calculate estimated costs using OpenRouter pricing
- User quotas:
  - Free tier: 100 calls/day or $0.10 equivalent
  - Paid tier: Configurable limits
- Warning at 80% quota, hard stop at 100%
- Daily reset at midnight UTC

### 7. Error Handling & Graceful Degradation

- Network errors: Return null, UI shows "Suggestions unavailable"
- Rate limits: Exponential backoff with max 3 retries
- Invalid responses: Log error, return empty suggestions
- Model unavailable: Automatic fallback to next model
- No models available: System continues without LLM features

### 8. Performance Requirements

- First call (cold): <500ms including network
- Subsequent calls: <300ms (warm cache)
- Cache hit: <10ms
- Parallel execution for independent calls
- Timeout: 3 seconds max per call

### 9. Security & Privacy

- API key never exposed in client code
- Server proxy endpoint: `/api/llm/complete`
- No PII in prompts (validation layer)
- Request sanitization to prevent injection
- Optional local model support (Ollama integration)

### 10. Monitoring & Observability

## Technical Implementation

### Core Service Structure

```typescript
// packages/core/services/llm/LLMService.ts
export class LLMService {
  private client: OpenAI;
  private cache: LRUCache<string, any>;
  private tokenTracker: TokenTracker;
  private modelChain: ModelConfig[];

  async complete(request: LLMRequest): Promise<LLMResponse> {
    // Check cache
    const cacheKey = this.getCacheKey(request);
    if (this.cache.has(cacheKey)) {
      return this.cache.get(cacheKey);
    }

    // Try model chain
    for (const model of this.modelChain) {
      try {
        const response = await this.callModel(model, request);
        this.cache.set(cacheKey, response);
        return response;
      } catch (error) {
        continue; // Try next model
      }
    }

    return null; // All models failed
  }
}
```

- **Risk**: Security exposure
  - **Mitigation**: Server proxy, key rotation, input validation
