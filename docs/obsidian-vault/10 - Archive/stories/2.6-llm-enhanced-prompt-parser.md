# Story 2.6: LLM-Enhanced Prompt Parser with Toggle

## Status

✅ COMPLETE - Integration tested and verified

## Story

**As a** prompt engineer working with complex prompts,
**I want** an LLM-powered parser that intelligently segments prompts based on semantic understanding with a toggle to switch between standard and LLM modes,
**So that** my prompts are parsed with proper context awareness rather than basic text splitting.

## Business Value

- **Improved Accuracy**: 90% better parsing accuracy for complex prompts
- **Semantic Understanding**: Creates appropriate node types based on content meaning
- **User Control**: Toggle allows users to choose parsing method based on needs
- **Time Savings**: Reduces manual graph construction time by 70%
- **Better Structure**: Automatically creates logical node relationships

## Acceptance Criteria

### 1. Parser Mode Toggle

- Toggle switch in UI (near paste/parse area)
- Two modes clearly labeled:
  - "Standard" - Basic text segmentation
  - "LLM-Enhanced" - Intelligent semantic parsing
- Visual indicator showing active mode (color/icon change)
- Toggle state persisted in localStorage
- Tooltip explaining the difference between modes

### 2. LLM Parser Intelligence

The LLM parser analyzes prompt structure and creates appropriate nodes:

**Character Definitions** → Variable Nodes

- Detects: "A warrior named Marcus", "The protagonist, Sarah"
- Creates: Variable node with name extraction

**Action Sequences** → WeightedChoice Nodes

- Detects: Lists of actions, behavioral options
- Creates: WeightedChoice with parsed options and default weights

**Scene Descriptions** → TextBlock Nodes

- Detects: Environmental descriptions, settings
- Creates: TextBlock nodes with formatted content

**Temporal Markers** → Sequential Nodes

- Detects: "First..., then..., finally..."
- Creates: Sequential nodes with proper ordering

**Mood/Tone Indicators** → Metadata

- Detects: Emotional context, atmosphere
- Adds: Metadata to relevant nodes

### 3. Parsing Behavior

- Parse button triggers the selected mode
- No suggestions or confirmations - direct parsing
- Progress indicator with cancel option for LLM processing
- Clear error messages if parsing fails
- Retry logic: 2 attempts before automatic fallback to standard
- Ambiguous detections logged as metadata for user review

### 4. Variable Preservation

- Variables like `{character_name}` preserved exactly
- References between nodes maintained
- Variable nodes automatically created for detected parameters
- Post-processing validation to prevent hallucinated variables
- Diff check against original prompt for variable integrity

### 5. Performance Requirements

- Standard mode: <100ms parsing time
- LLM mode: <2 seconds for average prompt (500 tokens)
- Graceful degradation if LLM service unavailable
- Caching of parsed patterns for similar prompts

### 6. Output Structure

- Nodes positioned using topological sort for logical flow
- Automatic edge creation between related nodes
- Proper node spacing (minimum 150px horizontal, 100px vertical)
- Groups related nodes visually with consistent layout
- LLM-suggested ordering preserved when logical

### Parser Service Enhancement

```typescript
// packages/core/services/PromptParser.ts
export interface ParserOptions {
  mode: 'standard' | 'llm-enhanced';
  preserveVariables: boolean;
  autoConnect: boolean;
}

export class PromptParser {
  private llmService: LLMService;
  private standardParser: StandardParser;

  async parse(prompt: string, options: ParserOptions): Promise<ParseResult> {
    if (options.mode === 'llm-enhanced') {
      try {
        return await this.llmEnhancedParse(prompt, options);
      } catch (error) {
        console.warn('LLM parse failed, falling back to standard', error);
        return this.standardParser.parse(prompt, options);
      }
    }

    return this.standardParser.parse(prompt, options);
  }

  private async llmEnhancedParse(
    prompt: string,
    options: ParserOptions
  ): Promise<ParseResult> {
    // Prepare context-aware prompt with few-shot examples
    const systemPrompt = `
      Analyze this prompt and create a node graph structure.
      Identify:
      - Characters → Variable nodes
      - Actions/choices → WeightedChoice nodes
      - Descriptions → TextBlock nodes
      - Sequences → Sequential nodes
      
      Preserve any {variable} syntax exactly.
      Handle multilingual content appropriately.
      
      Example:
      Input: "The hero {name} fights the dragon then escapes to the castle."
      Output: {
        "nodes": [
          {"type": "Variable", "content": "{name}", "metadata": {"role": "hero"}},
          {"type": "Sequential", "content": "fights the dragon", "metadata": {"action": "combat"}},
          {"type": "Sequential", "content": "escapes to the castle", "metadata": {"action": "movement"}}
        ],
        "edges": [
          {"source": 0, "target": 1},
          {"source": 1, "target": 2}
        ]
      }
      
      Return valid JSON with nodes array and edges array.
    `;

    const response = await this.llmService.complete({
      prompt: systemPrompt,
      userContent: prompt,
      model: 'gpt-4o-mini',
      temperature: 0.3,
      responseFormat: 'json'
    });

    return this.processLLMResponse(response, options);
  }
}
```

### LLM Response Processing with Validation

```typescript
// packages/core/services/LLMResponseProcessor.ts
import { z } from 'zod';

// Zod schema for LLM response validation
const LLMResponseSchema = z.object({
  nodes: z.array(
    z.object({
      type: z.enum(['Variable', 'WeightedChoice', 'TextBlock', 'Sequential']),
      content: z.string(),
      metadata: z.record(z.any()).optional(),
      variables: z.array(z.string()).optional()
    })
  ),
  edges: z.array(
    z.object({
      source: z.number(),
      target: z.number(),
      label: z.string().optional()
    })
  )
});

export class LLMResponseProcessor {
  async processResponse(
    response: unknown,
    originalPrompt: string,
    options: ParserOptions
  ): Promise<ParseResult> {
    // Validate response structure
    const validated = await this.validateResponse(response);
    if (!validated) {
      throw new Error('Invalid LLM response structure');
    }

    const nodes: Node[] = [];
    const edges: Edge[] = [];

    // Convert LLM response to React Flow nodes
    validated.nodes.forEach((nodeData, index) => {
      const node = this.createNode(nodeData, index);
      nodes.push(node);

      // Extract and preserve variables with validation
      if (nodeData.variables && options.preserveVariables) {
        const validVariables = this.validateVariables(
          nodeData.variables,
          originalPrompt
        );
        validVariables.forEach(varName => {
          this.createVariableNode(varName, nodes);
        });
      }
    });

    // Create edges with validation
    if (options.autoConnect) {
      validated.edges.forEach(edgeData => {
        if (this.validateEdge(edgeData, nodes.length)) {
          edges.push(this.createEdge(edgeData, nodes));
        }
      });
    }

    return {
      nodes: this.layoutNodesWithTopologicalSort(nodes, edges),
      edges,
      metadata: this.extractGlobalMetadata(validated)
    };
  }

  private async validateResponse(
    response: unknown
  ): Promise<LLMParseResponse | null> {
    try {
      return LLMResponseSchema.parse(response);
    } catch (error) {
      console.error('LLM response validation failed:', error);
      return null;
    }
  }

  private validateVariables(
    variables: string[],
    originalPrompt: string
  ): string[] {
    // Only keep variables that exist in the original prompt
```

### Security & Privacy Handler

```typescript
// packages/core/services/ParserSecurity.ts
export class ParserSecurity {
  sanitizePrompt(prompt: string): string {
    // Remove potential PII patterns
    const sanitized = prompt
      .replace(/\b[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,}\b/gi, '[EMAIL]')
      .replace(/\b\d{3}[-.]?\d{3}[-.]?\d{4}\b/g, '[PHONE]')
      .replace(/\b\d{3}-\d{2}-\d{4}\b/g, '[SSN]');

    // Prevent prompt injection
    const cleaned = this.escapeInjectionPatterns(sanitized);

    return cleaned;
  }

  private escapeInjectionPatterns(text: string): string {
    // Remove potential injection commands
    const patterns = [
      /ignore (previous|all) instructions/gi,
      /system:/gi,
      /\[INST\]/gi,
      /<\|im_start\|>/gi
    ];

    let cleaned = text;
    patterns.forEach(pattern => {
      cleaned = cleaned.replace(pattern, '');
    });

    return cleaned;
  }

  validateOutputSafety(response: any): boolean {
    // Check for suspicious patterns in LLM output
    const suspicious = ['eval(', 'Function(', '__proto__', 'constructor'];

    const responseStr = JSON.stringify(response);
    return !suspicious.some(pattern => responseStr.includes(pattern));
  }
}
```

### Fallback Handler

```typescript
// packages/core/services/ParserFallback.ts
export class ParserFallback {
  private standardParser: StandardParser;

  async handleLLMFailure(
    prompt: string,
    error: Error,
    options: ParserOptions
  ): Promise<ParseResult> {
    // Log error for monitoring
    console.error('LLM parsing failed:', error);

    // Notify user of fallback
    this.notifyUser('Using standard parser due to LLM unavailability');

    // Use standard parser with enhanced heuristics
    const result = await this.standardParser.parse(prompt, {
      ...options,
      useEnhancedHeuristics: true
    });

    // Add metadata indicating fallback was used
    result.metadata = {
      ...result.metadata,
      parserMode: 'standard-fallback',
      fallbackReason: error.message
    };

    return result;
  }
}
```
